# Contributing to WorkLaw / USAAssist

A few conventions keep this repo's multi-actor workflow (humans + automated agents) from colliding.

## Branch flow — land changes on `auto/agents` first

**All changes go to `auto/agents` first, never directly to `main`.**

`main` is the production branch: GitHub Pages (furrball26.github.io/USAAssist) auto-publishes `index.html` from it on every push, and the worklaw.app Vercel shell is deployed from a `main` commit SHA. Pushing straight to `main` while other work is in flight on `auto/agents` forks the two branches and forces a messy reconcile (this happened 2026-08-28: a squashed review-fix commit landed on `main` while the same work — plus more — was already on `auto/agents`).

Workflow:
1. Commit to `auto/agents` (one logical change per commit).
2. Green-gate: `npm run verify` must pass (build + validators + the full Puppeteer suite).
3. Push `auto/agents`.
4. Deploy = fast-forward `main` to `auto/agents` (`git push origin auto/agents:main`); Pages publishes automatically. For worklaw.app, re-render + upload the Vercel shell (see README "Deployment").

Keep `auto/agents` and `main` aligned — reconcile onto `auto/agents`, then fast-forward `main`.

## Editing rules

- **Edit `index.dev.html` only** — `index.html` and `assets/app.js` are generated by `node build.mjs`. Never hand-edit the built artifacts (and never hand-merge them in a conflict — resolve `index.dev.html`, then rebuild).
- **Legal content** (`content/**`) stays `reviewed:false` until counsel signs off. Don't flip `reviewed` flags.
- Run `npm run verify` before every push; it's the real gate (the `test` script is only a subset).

## Two gotchas

- **`workflow` OAuth scope:** pushing any change to `.github/workflows/*` requires the GitHub token to have `workflow` scope (`gh auth refresh -s workflow`). Without it the push is rejected outright.
- **CI needs Chrome at `./chrome-headless-shell`:** the Puppeteer suites `find ./chrome-headless-shell`, so CI installs it with `npx @puppeteer/browsers install chrome-headless-shell --path .`. A default-cache install (no `--path .`) leaves CI unable to find the browser.
